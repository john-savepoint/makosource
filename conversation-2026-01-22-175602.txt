  Feasibility Assessment: Custom Language Selection Menu for FF7

  Summary of Findings

  ★ Insight ─────────────────────────────────────
  The FF7 executable uses a well-defined game mode system at word_CC0D84 that
  manages transitions between Field (1), World Map (2), Battle (3), Menu (5),
  and other states. The menu system prints "START OF MENU SYSTEM!!!" and "END OF
   MENU SYSTEM!!!" debug strings, indicating Square's original developers built
  clear separation between game modes.
  ─────────────────────────────────────────────────

  Key Discoveries

  1. Game Mode State Machine
  ┌──────────┬────────────────────┬─────────────┐
  │ Mode ID  │    Description     │ Address Set │
  ├──────────┼────────────────────┼─────────────┤
  │ 0        │ Init/Title         │ 0x408EBA    │
  ├──────────┼────────────────────┼─────────────┤
  │ 1        │ Field              │ 0x60E542    │
  ├──────────┼────────────────────┼─────────────┤
  │ 2        │ World Map          │ 0x41CB24    │
  ├──────────┼────────────────────┼─────────────┤
  │ 3        │ Battle             │ 0x74BE09    │
  ├──────────┼────────────────────┼─────────────┤
  │ 5        │ Menu System        │ 0x6CC89A    │
  ├──────────┼────────────────────┼─────────────┤
  │ 6        │ Chocobo            │ 0x650383    │
  ├──────────┼────────────────────┼─────────────┤
  │ 0xD (13) │ Game Over/Continue │ 0x40989D    │
  └──────────┴────────────────────┴─────────────┘
  State Variable: word_CC0D84 (66 references across the codebase)

  2. Menu System Entry Points

  - Menu Initialization: sub_6CD3B0 (prints "START OF MENU SYSTEM!!!")
  - Menu Active Flag: dword_DC12DC (18 references)
  - Menu Window Coordinates:
    - X Position: dword_DC105C (88 references!)
    - Y Position: dword_DC1060
    - Width: dword_DC1064 (320 = 0x140)
    - Height: dword_DC1068 (240 = 0xF0)

  3. Text Rendering Functions

  - Character Drawing: sub_66E272 (881 bytes) - The main character rendering
  function
  - Font Info Table: 0x99DDA8 - Character width data
  - Debug Print: sub_664E30 - Used for logging

  4. Available Code Space
  ┌────────────────┬──────────────────┬───────────────────────────┐
  │     Region     │       Size       │           Notes           │
  ├────────────────┼──────────────────┼───────────────────────────┤
  │ .text padding  │ 459 bytes        │ Only actual padding found │
  ├────────────────┼──────────────────┼───────────────────────────┤
  │ .rdata padding │ 324 bytes        │ Read-only data            │
  ├────────────────┼──────────────────┼───────────────────────────┤
  │ .bind padding  │ ~768 bytes total │ Scattered                 │
  └────────────────┴──────────────────┴───────────────────────────┘
  Finding: Very limited native code cave space in the EXE itself (~1.5KB total
  usable).

  Feasibility Assessment

  Option A: Pure Hext/EXE Patching

  Feasibility: LOW ⚠️

  Pros:
  - No FFNx dependency
  - Works with vanilla game

  Cons:
  - Only ~1.5KB of code cave space available
  - Would need to overwrite existing (possibly useful) padding
  - Complex state management in assembly
  - No easy way to store language selection persistently
  - Risk of conflicts with other mods

  Option B: FFNx Hook + Minimal EXE Patches

  Feasibility: HIGH ✅

  Approach:
  1. Use FFNx's C++ hook system to implement the menu logic
  2. Create a new "Language Select" mode (use unused mode ID like 0x1D or 0x1E)
  3. Hook into the game mode dispatcher (sub_4090E6)
  4. Render custom menu using FFNx's BGFX rendering (bypasses game's rendering)
  5. Store selection in FFNx.toml configuration

  Implementation Strategy:
  // In FFNx src/ff7/language_menu.cpp
  void render_language_menu() {
      // Use BGFX to draw a simple menu overlay
      // Options: English, Japanese, German, French, Spanish

      // Draw background box
      draw_menu_box(100, 80, 120, 100);

      // Draw text options
      draw_text("Select Language", 110, 90);
      draw_text("> English", 110, 110);
      draw_text("  日本語", 110, 130);
      // ...

      // Handle input
      if (input_confirm()) {
          set_language(current_selection);
          // Return to title screen (mode 0)
          *game_mode = 0;
      }
  }

  Hext Patch (minimal):
  # Add language menu as mode 0x1D (29)
  # Hook into mode dispatcher to recognize new mode

  +0x409XXX  # Find appropriate switch location
  CMP word ptr [CC0D84], 1Dh
  JNZ @skip_lang_menu
  CALL [FFNx_language_menu_ptr]
  JMP @end_switch
  @skip_lang_menu:

  Option C: Intercept Title Screen

  Feasibility: MEDIUM ⚡

  Approach:
  1. Hook the title screen initialization
  2. Display language selection BEFORE showing New Game/Continue
  3. Less invasive than new mode

  Challenge: Title screen is mode 0, would need careful integration

  Recommended Approach

  Option B (FFNx Hook + Minimal EXE Patches) is the most practical approach
  because:

  1. Sufficient Code Space: FFNx is a DLL with unlimited code space for new
  features
  2. Clean Architecture: Leverages existing FFNx hook infrastructure
  3. Persistent Storage: Can save language preference to FFNx.toml
  4. Compatibility: Works alongside other FFNx features and mods
  5. Maintainability: C++ code is easier to maintain than assembly patches

  Implementation Requirements

  FFNx Modifications:
  1. Add language_menu.cpp with menu rendering logic
  2. Add hotkey hook (e.g., F12 during title screen to show language menu)
  3. Add config option enable_language_selector = true
  4. Implement font/kernel.bin hot-swapping based on selection

  Hext Patches:
  1. Small dispatcher hook to recognize custom menu mode (~20 bytes)
  2. Export FFNx function pointer for game to call

  Assets Needed:
  1. Language menu texture (optional - can use existing font)
  2. Localized kernel.bin files for each language
  3. Localized field dialogue files

  Conclusion

  Yes, it is feasible to create a custom language selection menu, but the most
  practical approach is through FFNx rather than pure EXE patching. The game's
  architecture with its clear mode state machine (word_CC0D84) makes adding a
  new menu mode quite achievable when combined with FFNx's hook system.
